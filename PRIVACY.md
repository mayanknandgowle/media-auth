# Privacy

Selected JPEG XMP creator-tool and three date strings are also displayed/exported, separately from EXIF. They may reveal sensitive software/time information and may be forged. Opaque author/GPS/title/history properties are not extracted; URLs/namespaces are never fetched. This bounded local parsing adds no telemetry, upload, retention or permissions. See [ADR 0014](docs/adr/0014-bounded-jpeg-xmp.md).

Selected EXIF PixelXDimension/PixelYDimension claims are also displayed/exported. A separately labeled numeric comparison uses the probe's encoded dimensions without orientation. Missing values do not imply agreement; differences can reflect padding or historical metadata and establish no cause or authenticity. This adds no acquisition, upload or persistence. See [ADR 0013](docs/adr/0013-exif-dimension-comparison.md).

MediaAuth performs analysis only after explicit user selection. The CLI reads the named local file. The extension also reads a file only when selected using its file chooser; local inspection requires no page access or network request. PNG/JPEG/WebP/GIF/BMP probing and inspection run locally; probes do not interpret metadata payloads or apply orientation. WebP probing checks metadata chunk presence for framing consistency but does not extract or report their contents. GIF comment/application payloads and palette contents are skipped without extraction or rendering; no timing or transparency observations are emitted. BMP probing reads fixed headers only; pixels, gaps, padding, and resolution fields are not interpreted. The descriptor-only `probe` command does not run analyzers or compute an identity. The extension inspects the active page only after the user invokes its workflow and requests discovery, then fetches only the selected same-origin image. Discovery temporarily records a bounded candidate list; it does not analyze every image.

JPEG, static WebP and static PNG inspection separately extract selected recorded EXIF camera/lens make/model, software, date/time strings and orientation from one pre-scan JPEG APP1 block, one WebP EXIF chunk, or one PNG eXIf chunk. These fields appear in reports/exports, may reveal sensitive device/time information, and can be forged. No dates or capture history are verified; orientation is not applied. GPS, owner/serial, maker notes, thumbnails, arbitrary directory graphs, XMP/IPTC/ICC and post-scan metadata are not extracted. Opaque bytes may still be held in acquired media memory; no stripping or guaranteed erasure is claimed. GIF/BMP metadata payloads remain uninterpreted. PNG CRC scanning reads opaque payload bytes without extracting their contents. See [ADR 0010](docs/adr/0010-bounded-jpeg-exif.md), [ADR 0011](docs/adr/0011-static-webp-exif.md) and [ADR 0012](docs/adr/0012-static-png-exif.md).

No analytics, telemetry, browsing history collection, accounts, raw-media database, automatic persistent result storage, or remote inference is implemented. Candidate selections and analysis results exist in memory. The side panel holds the displayed result until replaced or closed; the service worker may retain a bounded selection list until replaced, expired on use, or suspended. There is no guarantee of cryptographic memory erasure.

Acquisition is a network GET to the selected asset's origin. It may be visible to that origin and the browser's networking/service-worker infrastructure. The request omits credentials and referrer, disallows redirects, and uses no-store caching. MediaAuth does not control the origin's logs, the browser's internal caches, or the page's own behavior. An origin may serve different bytes on a later request.

Reports preserve acquisition context: local file, original web asset, blob, screen capture, or other. The initial extension does not capture screenshots. Future capture workflows must explain which original metadata/provenance/signals were lost. Never describe screen-derived pixels as an original asset.

CLI JSON may contain a local file label; recorded EXIF fields and results can reveal sensitive information. Users control whether to save or share stdout. The extension can explicitly download the current report as JSON, including a bounded local filename when selected. Export contains evidence and acquisition context, never raw-media bytes. Clear forgets the current report and worker page selections; it cannot erase exported reports or browser-managed download history. Avoid placing real private media in test fixtures, logs, bug reports, or commits.

Any future cloud inference must be explicitly opt-in, disclose destination and data before upload, provide meaningful cancellation and retention controls, and update this policy. Core's remote capability gate is a foundation for that consent boundary, not a shipped cloud service.
