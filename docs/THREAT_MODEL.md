# Foundation threat model

## Assets and trust boundaries

Protect selected media confidentiality, browser/page access, filesystem access, resource availability, and truthful evidence interpretation. Inputs include hostile files, mutable local paths, hostile page DOM/URLs, extension messages, and malformed analyzer results. Chrome's extension process and the operating system are trusted. Shipping analyzers are trusted application code; malicious executable plugins are outside the current supported deployment.

| Boundary / threat                                                                | Current control                                                                                                                          | Remaining limit                                                                                                                         |
| -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| File path becomes a directory, device, FIFO, symlink, or changes during analysis | Reject nonregular/symlink paths; platform nonblocking/no-follow flags; compare stat/fstat identity; check around reads; close in finally | Hostile filesystems can evade timestamp/identity checks; no immutable filesystem snapshot guarantee                                     |
| Huge media, malicious lengths, many tiny chunks                                  | 8 MiB default, safe-integer checks, explicit range/stream size/count budgets, 40M pixel cap                                              | Limits are deployment policy; increased limits require profiling                                                                        |
| PNG corruption/pathological compression                                          | Validate selected framing/order, IHDR constraints and CRCs; bounded reads; no decompression                                              | CRC is not cryptographic integrity; compressed image data and all ancillary semantics are not validated                                 |
| Parser exploit/decompression bomb                                                | Minimal noninflating parser; no image decoding or metadata decompression                                                                 | Future parsers need isolated workers/processes and deadlines                                                                            |
| Arbitrary URL download / SSRF                                                    | No network CLI/server; extension accepts only registered same-origin HTTP(S) image selections; reject credentials and redirects          | A same-origin resource can still have side effects on GET; explicit selection is required; page/service worker may supply changed bytes |
| Origin or navigation confusion                                                   | Active-tab invocation; top-frame isolated injection bound to documentId; selection bound to tab/URL/expiry; check current tab            | No original publisher verification; an original asset means retrieved asset bytes rather than a screenshot                              |
| Privileged extension message spoofing                                            | Exact extension sender ID/panel URL, request shape validation, opaque selected IDs; no external messaging/content listener               | Trusted extension code or compromised browser remains privileged                                                                        |
| Unbounded response/slow server                                                   | Streaming decoded-body limit, maximum chunks, 10-second AbortController timeout, one operation at a time                                 | Browser internally manages network buffers; abort is not a CPU isolation boundary                                                       |
| DOM/metadata XSS                                                                 | UI creates elements and assigns textContent; no HTML rendering of observations, no remote scripts                                        | Future rich rendering must preserve this boundary                                                                                       |
| Plugin lies or malformed JSON                                                    | Registry metadata validation, evidence schema/attribution/status/size checks, separate confidence/quality, conservative fusion           | Contract-valid evidence can still be false; trusted code can stall or allocate before returning                                         |
| Silent upload or browsing surveillance                                           | No remote analyzer shipped; remote execution opt-in gate; no passive scripts/history/storage/telemetry                                   | New remote adapters need visible consent and privacy review                                                                             |
| Fake certainty                                                                   | Unavailable and absence distinct; no authenticity scoring; provenance placeholders never claim absence/verification                      | Future fusion needs trust models, calibration, independent evaluation                                                                   |

## Resource contract

`DEFAULT_LIMITS` specifies `maxBytes`, `maxPixels`, `maxChunkBytes`, and `maxChunks`. Clients validate before reads; probes/hash adapters validate again so direct calls remain bounded. The filesystem and PNG scanner use at most 64 KiB per range read. Browser bytes are held in bounded memory for messaging and WebCrypto, with several temporary representations; the 8 MiB cap is not a promise of an 8 MiB peak memory footprint. Concurrent panel requests are rejected while an operation runs.

Cancellation in core is cooperative. A promise timeout cannot stop an in-process analyzer, and no hard timeout is claimed. Untrusted third-party analyzers must not be loaded until an isolation protocol and enforcement mechanism exist. Remote opt-in is a capability gate for trusted adapters, not a network sandbox.

## Tests and review

Tests cover malformed/truncated/CRC-invalid PNGs, oversized dimensions/bytes/chunks, undersupplied/oversupplied streams, hash vectors, failed/invalid analyzers, duplicate registry/evidence IDs, remote opt-in, cancellation, unsafe URLs, invalid senders/messages, stale selections, and acquisition timeouts. Browser smoke and manual host UI checks have distinct scopes; see [VALIDATION.md](VALIDATION.md).

Before adding a format, provider, remote service, or permission: identify new trust boundaries, add adversarial fixtures, define budgets, update documentation, and record any major decision. Do not add a user-supplied URL fetch API.
