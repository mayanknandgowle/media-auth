# Foundation threat model

## Assets and trust boundaries

Protect selected media confidentiality, browser/page access, filesystem access, resource availability, and truthful evidence interpretation. Inputs include hostile files, mutable local paths, hostile page DOM/URLs, extension messages, and malformed analyzer results. Chrome's extension process and the operating system are trusted. Shipping analyzers are trusted application code; malicious executable plugins are outside the current supported deployment.

| File path becomes a directory, device, FIFO, symlink, or changes during analysis | Reject nonregular/symlink paths; platform nonblocking/no-follow flags; compare stat/fstat identity; check around reads; close in finally | Hostile filesystems can evade timestamp/identity checks; no immutable filesystem snapshot guarantee                                     |

## JPEG scope

The CLI JPEG probe checks selected marker, frame, and scan framing with a forward buffer. Lengths are checked before reading or skipping; only small frame/scan headers are copied. Each marker, including SOI, EOI, and restart markers, counts against `maxChunks`. Segment payloads and entropy intervals obey `maxChunkBytes`; marker fill bytes are bounded by `maxBytes`. The reader requests at most the smaller of 64 KiB and `maxChunkBytes`. Dimensions obey `maxPixels`.

JPEG coding tables, full progressive scan progression, entropy correctness, restart MCU intervals, metadata payloads, and orientation are not validated. Successful framing inspection is not a promise of decodability or authenticity. Unsupported processes, deferred height, and trailing/concatenated streams are rejected. There is no decoder or additional native/runtime dependency. The extension uses all five documented probe subsets for explicit local/page inspection.

## WebP scope

The CLI WebP probe reads at most 12 bytes per range request, further split by `maxChunkBytes`. All allocations are fixed-size header buffers; no allocation depends on a declared chunk length or canvas pixel count. Validate known size/limits before access, exact RIFF extent, chunk bounds and zero padding, and chunk count/payload budgets, including unknown and metadata chunks. Pixel limits apply to both extended canvas and image headers. Reconstruction ordering, unique images, selected alpha/header fields, and metadata presence flags are checked.

Compressed color/alpha data and ICCP/EXIF/XMP contents are skipped and unvalidated. Unknown chunks are skipped; metadata stays `NOT_PROBED`. A successful probe does not establish decodability, transparency, or authenticity. The strict subset rejects animation, scaled VP8, duplicate metadata, and trailing files. No new dependency, network access, retention, or extension permission is introduced. See [ADR 0005](adr/0005-static-webp-probe.md).

## GIF scope

The CLI GIF probe reads only fixed headers of at most 13 bytes, further split by `maxChunkBytes`. Palettes, compressed image data, and comment/application contents are skipped after extent checks. No allocation scales with dimensions or declared payload sizes. The logical-screen pixel cap also bounds its contained image. Reject multiple images, unsupported rendering/control/extension types, invalid palette indices and reserved fields, missing active palettes, and nonexact trailers.

Count every top-level block, palette, fixed extension sub-block, and data sub-block including zero terminators; the header/logical-screen pair counts as one. Per-payload and aggregate sub-block-chain byte limits prevent splitting a large payload from bypassing its budget. Tiny empty comments still consume count budget. See [ADR 0006](adr/0006-single-image-gif-probe.md) for exact accounting and deliberate compatibility restrictions.

LZW codes, palette colors, metadata, timing/looping, disposal rendering, and transparency are unvalidated; structurally accepted data can be undecodable. No decompression is attempted and no authenticity inference is made. The probe requires a trustworthy exact-range adapter and cannot impose a hard timeout on arbitrary adapter code. The existing local-file adapter checks identity/changes and closes its handle. No permissions, remote requests, or dependencies are added.

## BMP scope

The CLI BMP probe accepts only the 40-byte info header and 24-bit BI_RGB data without color-table declarations. Read fixed headers only, at most 40 bytes per allocation/request and further split by `maxChunkBytes`. Require a matching file size, zero reserved fields, valid signed dimensions/plane count, bounded pixel offset, exact padded-row extent, and consistent optional image-size declaration. Reject unsupported headers, depths, compression, palettes, and trailing bytes.

Use division before multiplying padded stride by absolute height; do not use bitwise stride calculations that wrap large widths. Count file header, DIB header, pixel array, and optional gap; bound array/gap payload sizes even though they are skipped. No pixels, padding, gap content, or resolution metadata are interpreted, and no decodability/authenticity inference follows. See [ADR 0007](adr/0007-24-bit-bmp-probe.md) for the strict subset.

## Resource contract

`DEFAULT_LIMITS` specifies `maxBytes`, `maxPixels`, `maxChunkBytes`, and `maxChunks`. Clients validate before reads; probes/hash adapters validate again so direct calls remain bounded. The filesystem and all probes cap range requests at the smaller of 64 KiB and maxChunkBytes. PNG includes fixed-header and CRC reads in that cap; payload budgets remain separate. Browser bytes are held in bounded memory for messaging and WebCrypto, with several temporary representations; the 8 MiB cap is not a promise of an 8 MiB peak memory footprint. Concurrent panel requests are rejected while an operation runs.

Cancellation in core is cooperative. A promise timeout cannot stop an in-process analyzer, and no hard timeout is claimed. Untrusted third-party analyzers must not be loaded until an isolation protocol and enforcement mechanism exist. Remote opt-in is a capability gate for trusted adapters, not a network sandbox.

The separate WebP EXIF analyzer scans the exact RIFF extent with independent chunk/payload/padding/flag checks before allocating at most one 64 KiB EXIF payload. Common range access and evidence mapping preserve JPEG semantics and the TIFF field bounds. No pixels, alpha, profile data or unknown payloads are decoded. A compatibility prefix is disclosed. Missing EXIF is not authenticity; see [ADR 0011](adr/0011-static-webp-exif.md).

The PNG eXIf analyzer separately bounds chunk extents, work (including CRC payload blocks) and a single 64 KiB metadata allocation. It checks every chunk CRC, retains only verified EXIF bytes, rejects ambiguous/late/prefixed metadata and never rereads a different unchecked payload for TIFF parsing. Later carrier failure discards all fields. Image/opaque payloads are streamed only for CRC, never decompressed; CRC is not an authenticity check. See [ADR 0012](adr/0012-static-png-exif.md).

## Tests and review

JPEG XMP uses bounded pre-scan segments and strict UTF-8, then a rejecting XML/RDF subset. DTDs/entity declarations, external resource qualifiers on selected fields, comments/CDATA/arbitrary PIs and extended packets are inconclusive. Predefined/numeric references decode once, never recursively. Namespace URIs are resolved as strings without network access; aliases cannot redirect selected claims to another namespace. Depth/node/attribute/namespace/name/value/work caps apply; duplicate/ambiguous selected properties and later failures discard all XMP fields. Opaque nested properties are not promoted to direct claims. Exports include selected tool/date claims, never authenticated history. Existing EXIF/hash stay separate; no added permissions/dependencies. See [ADR 0014](adr/0014-bounded-jpeg-xmp.md).

EXIF dimension values are positive inline SHORT/LONG scalars, bounded by their representation; they never control pixel allocation or replace probed dimensions. Malformed type/count/zero/duplicate tags discard all EXIF fields. Partial pairs remain recorded with comparison unavailable. A separately tagged numeric comparison preserves both pairs; matches/differences infer no authenticity, manipulation or cause. The extension recomputes supplied comparison states/pairs/reasons at its report boundary and renders only text. Existing directory/entry/cancellation limits apply; no new reads, dependencies or permissions. See [ADR 0013](adr/0013-exif-dimension-comparison.md).

The JPEG EXIF analyzer independently validates limits and byte access. It bounds one pre-scan APP1 allocation, 4 KiB requests, markers/fill bytes, two directories, entry counts and text length; offsets are checked before access. Overlap/cycles, duplicates and malformed selected fields discard partial observations. Unknown payloads and GPS/owner/serial, maker notes, thumbnails and next-IFD graphs are never followed. Recorded dates, camera/software and orientation are attacker-controlled strings/numbers, rendered as text and never promoted to provenance/authenticity. Missing pre-scan EXIF does not establish absence of all metadata. Exports can disclose selected recorded fields; see [ADR 0010](adr/0010-bounded-jpeg-exif.md).

Tests cover malformed/truncated/CRC-invalid PNGs, malformed/truncated JPEG frame and scan headers, stuffing/restart errors, JPEG marker/entropy budgets and range-adapter contracts, oversized dimensions/bytes/chunks, undersupplied/oversupplied streams, hash vectors, failed/invalid analyzers, duplicate registry/evidence IDs, remote opt-in, cancellation, unsafe URLs, invalid senders/messages, stale selections, and acquisition timeouts. Browser smoke and manual host UI checks have distinct scopes; see [VALIDATION.md](VALIDATION.md).

Before adding a format, provider, remote service, or permission: identify new trust boundaries, add adversarial fixtures, define budgets, update documentation, and record any major decision. Do not add a user-supplied URL fetch API.

The [cross-format corpus](PROBE_CORPUS.md) runs named errors, deterministic truncations/byte mutations, and concatenations with a guarded adapter. It detects out-of-range or over-budget requests and unexpected exceptions; explicit PNG CRC-boundary and CLI read-limit regressions cover demonstrated fixes. Its finite read ceiling is test-side instrumentation, not a production timeout or exhaustive security audit.

## Test-only stress containment

The [seeded stress runner](PROBE_STRESS.md) bounds generated input/edit/case counts and runs existing probes in a worker terminated by a parent deadline. Range-guard violations remain failures even if caught by the probe. V8 heap/stack caps are not total-memory limits and the worker is not a security sandbox. Generated cases are original synthetic bytes retained only in memory. No production execution, acquisition, permission, or privacy boundary changes; see [ADR 0008](adr/0008-test-only-probe-stress-worker.md).

## Selected local files and report export

The panel file adapter checks declared size before reader creation/allocation and enforces exact stream size, chunk count/size, and an acquisition deadline. It cancels/releases readers on completion/failure; byte-signature probes enforce their usual pixel/structure budgets. Local-file access does not use page scripting, arbitrary filesystem paths, or runtime media messages.

Report presentation applies JSON/evidence budgets, validates facts/hash encoding and conclusion references, and renders untrusted strings with textContent. Exports use a fixed download name and a revoked object URL, with a user click required; no media bytes or HTML are exported. New/failed operations disable the previous export. Authenticated exact `CLEAR` requests drop worker selections without needing page access. No new permissions or relaxed CSP. Browser download handling remains part of the browser trust boundary; see [ADR 0009](adr/0009-local-image-inspection-client.md).

## Static WebP XMP

The WebP XMP adapter shares the RIFF scanner with EXIF while independently checking its selected chunk/flag. Exact extent, lengths/zero padding, unique metadata, static image presence and animation rejection precede payload parsing; later failures discard fields. A 65,504-byte project packet cap applies before allocation, alongside input/chunk/work and 4 KiB range bounds. The existing rejecting XML subset and no-network/entity policy apply unchanged. EXIF limits/semantics remain intact; broader reconstruction validation remains the media probe responsibility. No new dependency/permission or authenticity inference; see [ADR 0015](adr/0015-static-webp-xmp.md).

## Uncompressed static PNG XMP

The XMP adapter shares the static PNG CRC/framing scanner with EXIF, preserving EXIF semantics/work limits. XMP text keywords are recognized during bounded CRC reads and exact selected bytes retained, never reread. A 65,526-byte selected-chunk allocation cap includes the 22-byte header and 65,504-byte XML cap. Identification reads at most the first 4 KiB CRC block before allocation rejection; unknown text values are never retained/inflated. Compressed/legacy carriers, nonempty language/translation and ambiguous packets are inconclusive; no inflater is called. Late CRC/framing failures discard all XMP. Shared XML limits and external-entity/network rejection remain; no new dependency/permission/inference. See [ADR 0016](adr/0016-static-png-xmp.md).
